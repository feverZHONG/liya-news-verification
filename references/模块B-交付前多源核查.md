## 模块 B · 交付前多源核查（原 news-verification）

**何时必查：** 体育比分（最高风险，2 独立来源）/ 统计数据 / 序列号 / 事件日期时效 / 动漫游戏改编 / 巨额头条 / 模型基准表。

- 比分：搜索词写 `球队A vs 球队B 比分`，snippet 无明确比分不编造；罕见高比分 3 源确认
- 数字：官方公告对齐；百分比×绝对数验算；口径一致（乘用车 vs 汽车）；巨额金额 2 源+出处
- **口播／评论稿里的数字先当二手**：跌幅必须分清盘后／盘前／收盘（口播常取最极端那个），「财报后跌 X%」还要回公司官方新闻页查**同日有无人事、诉讼、指引下调等另一个触发器**——评论常只留下对自己论点有利的那一个。结论里把「数字偏高」与「归因漏项」分开写，别混成一句。
- **热度指标 ≠ 能力证据**：GitHub star／播放量／霸榜只能证明声量。一手查法 `api.github.com/search/repositories?q=<name>`（一次拿 stars／created_at／pushed_at，别爬网页）；虚高看 fork/star 比、短期批量建仓、社区刷星质疑，没有正面证据就只写「未证实」。评论型视频的整套报告流程（骨架／四档判定／群聊版）→ `bili-video-content` §二c ＋ `references/commentary-report.md`
- **厂商自家宣传图上的第三方评分／数据＝高点快照，不能当事实引**：官方海报会贴开分、峰值或挑最好那一家（实测：官方图写 OpenCritic 92／Metacritic 89，同期汇总站为 91／88）。评分类一律回汇总站或 ≥2 家媒体稿核一次；落档与出口写「官方口径 X／汇总口径 Y」，出口只报可复核那组——宣传数字进不了事实层
- **「我花了 N 亿 token／N 个月做成了 X」类个人技术宣称**：三层分开判，别揉成一句「真的假的」——① **成果层**：画面／仓库／工程目录能不能证「真做出来了」（能跑＝成立）；② **数字层**：token／工时／费用是自述，没账单或用量画面就标「自述」，再**换算成可比量级**判断离不离谱。**换算必须按三档单价拆开算**：缓存命中／缓存未命中／输出——只用一档单价乘总量会高估数倍（输出单价约为命中价的 200 倍，而缓存只作用于输入侧）。agent 式编程的常见结构是**输出占 2–10%＋输入命中率 80–95%**，这两个参数一换，同一条宣称能从「几万块」掉到「几千块」。**别背价**：估价前现读厂商官方 pricing 页（有中文页，三档齐全，还常分高峰/空闲半价，空闲时段正好覆盖夜间与法定节假日）；再把总额 ÷ 工程时间算每天／每秒速率——速率超出单会话可能的量级，只能写「必须大规模并行才成立」。算完两条结论要分开：**数字可换算 ≠ 数字被证实**（无账单仍是自述），**便宜 ≠ 成果大**。算法与矩阵见 `references/ai-usage-cost-estimation.md`；③ **归属层**：「我完成了」常只成立一半——查历史视频简介里的仓库链接、评论区 UP 自述、工程文件时间戳，分清**自研部分**与**拿来的开源／社区成果**。数值大既不能证明贵，也不能证明成果大，别替宣称做放大器。**同一波里连着出现「300 亿／100 亿／70 亿／10 亿 token」这类同构标题 ⇒ 这串数字已退化成标题模板**，按修辞读、不按投入记录读；拿它跟别人比大小毫无意义，能比的只有成果层（能不能跑、谁做完了）
- **「某公司开源了 X」类发布：判据在仓库，不在口播/媒体**：`api.github.com/orgs/<org>/repos?per_page=100&sort=updated`（新仓就在更新序里）→ `/repos/<org>/<repo>` 的 `created_at`/license → `/commits` 的**首提交时间（UTC 换 +8）**才是真实首发日，媒体写的「某日开源」拿它核。官方边界（哪些没开源、与内部版体差多少、支持哪些硬件）只有仓库 README 与 `doc/*.md` 写得清，媒体只作交叉印证。**官方数字先过三问**：收入还是利润（成本口径哪来）／谷价还是峰价（下限还是均值）／单点还是全局（单集群・单卡・全公司不是一回事）；二手再乘出来的数（「一张卡月入 18 万」）标推算，不进事实层
- 时效：date 字段比对；B站吃瓜看 pubdate 不看标题播放量；多 docid 取最早=首发；GitHub/官网看 pushed_at/meta description
- 红线：类别时效（新闻今日~昨日 / 科技 2 天内 / 报告 1 周内标日期）
- **时效核查前先取当前时间**：判断「这日期是不是未来／是不是假消息」之前先跑 宿主的时间命令（作者环境是 `bin/now`）。长会话跨天时**早先读到的时间锚点全部作废**——拿前一天的「今天」去判，会把今晨的报道当成不可能存在的未来新闻，白绕一圈；日期不确定就用工具读，别用推理填时间空缺
- **讣闻/生死类核查链**：一手＝官方讣告 → 央媒独立采写 → 百科生卒；单来源不算，口径不用娱乐化语气 → `references/verification-details.md`
- **相对时间的预报/推算值要带到期复核，跳票后不再续推算日期**：官方只给「2~3 周后」「下个月」这类相对量时，落档明标「推算·待核」并定一个到期点；到期回一手源核（官方公告接口／官方站 News／官方 SNS），没发生就把结论改成**不带日期的活口**（「等它出现」）——**别再续一个新的推算日期**：连着报假窗口，等于把自己的预告变成噪音（判例：DevNote「2~3 周后」→ 窗口到期仍未发，改活口后不再自造日期）
- **服务故障／事后补偿类（某平台「崩了」＋随后发钱）**：① **故障窗口以官方状态页／用户端站内通知为准**，媒体写的「近 N 小时」是约数（实测 4h53m 写成「近 5 小时」），**不算口径冲突**；② **口径层级＝官方站内通知 ＞ 官方署名帖（个人账号） ＞ 媒体稿 ＞ 社区帖**，落档写明用了哪一层（判例：同一事故，站内通知给 8:11–13:04，媒体只给「近 5 小时」，两者一致）；③ **补偿条款拆三件——现金 vs 赠金/代金券、有没有封顶、适用范围**：媒体只报机制（「按 7 日消耗全额返还」）**不报尾部**，没封顶时金额随账号量级线性放大，尾部能到数百万（实测用户端余额挂件 638 万／464 万 CNY）——「是不是普发」也要核：**客户级补偿与人人有份的活动是两回事**；④ **赠金性质＝只能站内抵扣、提不了现**，等于把未来用量锁在平台（「说返就返」不昂贵）；别把赠金当现金等价物写进结论，也别用单个人的返还额推全体
- **「全球性故障／大批站点维护」类事件**：先分**主动下线**与**被攻破**——维护页／紧急维护公告＝运营方在补丁落地前自己关门（判据：站内维护页＋「終了時刻未定」＋事后没有回滚／数据泄露通报／道歉）。「**有漏洞 ≠ 已沦陷**」：在野探测与攻击尝试可以很多（多家安全厂商各自有传感器），公开确认的大规模失陷为零时，结论只能写「尝试」。**同日常有第二件不相干的大事**（另一国的 CA 私钥缺陷、另一门语言的 CVE），社区会把它们拧成一根绳并给出「某国干的」这类归因——回一手源核**谁发现／谁受影响／谁被处理**，三者对不上就分节写，不顺着归因走。**规模数字认口径**：「X% 的网站跑这个」＝潜在暴露面，≠「X% 的网站出事」；同理「占大头」不等于「都挂了」
- **「它关停了」要分层验，别拿一个端口下结论**：网页不通（80/443）≠ 服务停了——业务端口（游戏网关／API／RPC）常由另一个进程守着，可能仍在监听。判据看**连接行为**：TCP 握手成功＝有进程在听；**快速 `Connection refused`（RST）＝端口没进程**；**超时（静默丢包）＝被过滤或主机不在**——三者含义不同，别一律写成「关了」。写之前做**同机同出口的前后对照**（此前通、现在不通才算变化），并排除本机到目标链路的问题，否则只能说「本侧不可达」。
- **「A 换成 B」类变更新闻（换供应商／换代理／换平台／换发行方）核三件**：① **历史基线**——先查清「之前是谁、维持了多久、当初为什么换」；它决定这条变化是**回归**还是转向（判例：美国肯德基由百事改可口可乐，中文读者的「回到旧时代」之所以成立，是因为 1986 年百事收购肯德基时它本是可口可乐的第二大汽水客户——官方稿只写「切换」，基线得自己查）；② **适用范围**——官方稿要点明运营实体与市场，「改」不等于全球改（同一品牌各市场主体不同，另一市场常不受影响）；③ **动机口径**——官方给的理由 ＋ 「是不是在为客流/业绩自救」这层商业化解读分开写，别把商业选择读成站队。
- **刚发生的事件「查不到二手报道」＝时间差，不是「不普遍」的证据**：第一手口径已到手、媒体还没跟进时，写法是「**第一手口径 ＋ 尚无媒体跟进**」＋留一个观察点（下次核官方渠道/榜单/媒体）；**别用「别处没写」暗示这是个人现象或存疑**——那会把用户手里的第一手降级成疑点。反向同理：用「有报道」当普遍性证据前，先看报道是不是同一源转载（见下「N 家媒体口径一致」条）。
- **驱动／补丁／推荐配置类口径会先后翻脸**：同一件事常同时挂着三套说法——官方运营指南、项目负责人亲口、硬件厂 hotfix 公告。定序＝**最晚发布 ＋ 作者层级最高**（负责人亲口 ＞ 官方运营指南 ＞ 第三方 hotfix）；旧条目**就地标「已被某日口径取代」而不是删掉**（读者会拿旧页面对账）。**hotfix 不是推荐驱动**：它基于旧正式版、修的是系统或别的作品的问题，不等于本作适配。
- **多源冲突取共识主流值+约数，精确差异进待验证区**
- **版本号 ↔ 年份：必须现查官方发版公告，版本号与日期成对写**（凭记忆或口述必错）→ `references/verification-details.md`

**「N 家媒体口径一致」可能是一源 N 转**（回溯到最早载体；物料发布时间 ≠ 事件时间）→ `references/verification-details.md`

**判「独立来源」看措辞，不看域名数**：两篇稿子换个站发不算两个源——**先比措辞与段落顺序**，整段逐字雷同、举例顺序一致、连错字都一样，那是同一次转抄（或同一份通稿），只能算 1 源。判独立的标准是「措辞不同 ＋ 各有对方没有的细节或原始出处」。攻略稿、背景考据稿、游戏资料站互抄最重（同一段设定介绍在多家站近乎逐字相同，错字一起继承）——找到两篇雷同稿＝还停在 1 源，继续换维度，别当「多源一致」写进结论。

**事件有「现场」而手上只有二手转述时**：开口要一手观察，别用推演填空（解释越圆越可疑）→ `references/verification-details.md`

**圈子里「某人作弊被封／世界纪录被下架／他是世界第一」类主张**：判**结果**用平台官方状态，别拿打假方或攞扶方的视频标题当证据——速通类走 speedrun.com API（账号 `role:banned` ＋ 名下 runs/PB 空＝一手实锤；HTML 页 403 是预期、API 200）；官方状态只能坐实「被封」，**坐实不了「用了什么手法」**，手法属举报方举证 → `references/speedrun-record-claims.md`

完整核查流程/搜索封锁对策/陷阱/基准口径 → `references/verification-details.md` + `references/benchmark-glossary.md`（验证日志属本机运行记录，不入本仓）

**「这产品归谁运营 / A 和 B 是不是同一家」类主体主张** → 官网页脚 ICP（一手）→ 隐私政策原文（「由 XX 运营」= 运营方实锤）→ 第三方备案查询补主体名与审核日 → 工商关联；争论当事人说辞只当线索。命令与坑（JS 渲染站点怎么绕、频控、法人≠运营方）见 `references/company-registry-check.md`（2026-09-12 沉淀，尘白×剑侠4 实例）。
