# 踩坑与专项（聊天记录/短信/VTuber）

> SKILL.md 留铁律+标准流程，本文件放踩坑表、聊天记录解析、短信钓鱼识别、VTuber 速查。

## 踩坑

| 坑 | 教训 |
|:---|:-----|
| 派 delegation 验证新闻 | 用户反馈"不要整太久"——简单搜索自己并行搜更快 |
| vision describe 认错标题 | 把千恋万花识别成千の刃濤 → 以搜索结果交叉验证为准 |
| 串行搜3组关键词 | 每次等结果回来再搜下一组 → 并行一次发3个 搜索入口（作者环境是 `mmx search`） |
| vision 整图被敏感词拦截 | 2026-08-01 实测：图含涉军内容时整图报 `input image sensitive` → **裁剪成上中下三段分别 describe**，不含敏感内容的分段能正常识别（含敏感内容那段仍会被拦，但通常能拿到大半数据） |
| **punycode 域名** | 收到 `xn--` 开头链接时确认真实域名：`label.encode("ascii").decode("punycode")`（**只解标签不带 TLD**，带 `.cn` 整体解报 UnicodeDecodeError）。解码出乱码/混搭（如 `xn--api-9v2hp48c` → `xn䬬--㭾api`）＝视觉伪装高信号，按高风险处理。2026-08-02 收藏夹批量扫描实测 |
| **甩图问数字：先搜真数再答** | 2026-08-05 Win11 更新截图问占用：经验估值「月更1.5-2.5G」，实际 25H2 累积更新全量 5479.4 MB，被用户纠正「你没搜一下验证才是真的」。大小/价格/版本/日期类数字先搜到真数（KB 补丁 → `windows-update-info` skill 的 catalog_size.py），实测标来源、估算标「估」，不许拿经验值当真数报 |
| **影视/游戏图：视觉模型只认角色不认版本** | 2026-08-03 表情包识别实测：94版三国曹操（鲍国安）vs 新三国（陈建斌）全被认成94版；周星驰礼帽西装造型多片撞车（回魂夜Leon vs 国产凌凌漆，靠**叼烟**细节区分）。多版本作品先确认版本，同款造型靠标志性道具细节区分 |
| **影视/游戏图：角色识别不确定时问用户场景线索** | 2026-08-03 三案（迪迦坠机二人组/逆转裁判3戈多/魔女审判）：视觉模型圈定大类后卡死，用户给一句场景/作品名（「迪迦胜利队飞机里」「逆转裁判3」「魔法少女的魔女审判」）就通了。**无文字图认不出时先问用户再搜，别自己在搜索里绕** |
| **甩图认角色：先射箭后画靶是大忌** | 2026-08-05 绿龟+双少女图：vision 三轮猜三个作品（少女与战车/少女前线/轻音少女），自己顺着「轻音」硬找证据（百度百科小豚猪鼻龟词条）坐实——结果用户纠正「少说了一样东西：neuro」+ 甩官方空间链接，实为 Neuro-sama 二创（右上=Neuro、左下=Evil Neuro、绿龟=社区龟梗）。教训：①vision 对同一图多次识别不收敛（发型/服装描述都会变），任何单次猜测=候选假设不是定论；②动物/道具物种特征只配生成假设（绿龟→猪鼻龟→轻音小豚），**不配坐实结论**——「搜到百科词条」只说明该动物在该作品里存在，不代表图里就是它；③用户说「少了东西/找XX」= 新线索，按新线索重查，别死守原结论；④外部 IP（VTuber/UP主/作品）用**官方渠道形象对比法**：拉官方 B 站空间头像/频道图比对角色特征，比纯搜索更快实锤（Neuro-sama 官方空间头像=棕发蓝眼红发饰白衣，图中右上女孩同款即锤） |
| **游戏对话框截图：名字框是硬线索** | 2026-08-03 两案：逆转裁判对话框标题「御剑」「戈多」直接点名角色，比视觉猜角色可靠（视觉把戈多猜成皇家骑士团）。游戏截图型识别最稳——游戏名/角色/台词全在画面里 |
| **同画面改字=同源变体** | 同一剧照/立绘换字幕是表情包常见玩法（同一张凌凌漆叼烟图两种配字）。识别到同画面不同字，登记时互挂关联不重复建档 |
| **自家角色先查自家档案** | 双生视界角色图：搜档案要覆盖 skins/ 立绘描述（搜「紫发」漏了时无瑕）；识别不确定时用 v3 跑 workspace 立绘目录对比，比反复搜网快且准 |

## 链接类验证的完整工具链

链接核查不止手动搜——`link-safety-check` skill 提供 `bin/linkcheck <url>`（静态特征：@伪装/裸IP/punycode/品牌仿冒/高危TLD/短链展开/跳转偏离 + 可选微步威胁情报核验），批量扫收藏夹用 `skills/link-safety-check/scripts/parse_bookmarks.py`。收到可疑链接先 linkcheck 拿分级再决定要不要搜。链接验证类任务优先走 link-safety-check，quick-fact-check 只做图片/文字/新闻类轻量验证。

## 聊天记录合集解析

收到聊天记录合集（合并转发嵌套/引用/图片附件），核心思路是**四步走，先结构后内容**：

1. **结构梳理** — 数外层条数，标记「合并转发消息」递归展开嵌套层（叠中叠），输出层级关系
2. **引用检查** — 每条「引用消息」确认被引内容是否在本合集内；不在的列出（引用者+内容摘要）→ 需要更早记录才补得全
3. **图片附件下载** — URL 是 `multimedia.nt.qq.com.cn/download?appid&fileid&rkey&spec=0`，用 python urllib 批量下（带 UA）；**bash 脚本里裸 `&` 会触发 Hermes 前台拦截**；下载完用 PIL 验格式，产物仅64字节=JSON错误页
4. **图片识别+核心提炼** — 视觉入口（作者环境是 `mmx vision describe`） 逐张看（提示词要问「表情包/截图/照片」定性+转录文字），重复 fileid 只识别一次，最后用一两句话概括整个合集要讲的事

**坑：** `appid is not match` = fileid 失效，换 UA/Referer 都没救；环境无 `file` 命令用 PIL 查格式；mmx 绝对路径 `<数据根>/.npm-global/bin/mmx`（后台 PATH 不含）。

### 群消息接收链路（2026-08-03 验证）——哪里会断信息

| 环节 | 会不会断 | 说明 |
|------|:---:|------|
| QQ 平台推送 | ⚠️ | 合并转发/聊天记录以引用消息（message_type=103）推送，`msg_elements[0].content` 是渲染好的「=== 消息 ===」文本；**直接发合并转发（不引用不@）content 可能为空，机器人收不到** |
| qqbot adapter | ✅ | `content = str(d.get("content",""))` 原样收，`_process_quoted_context` 完整提取 msg_elements 文本+附件，无长度截断 |
| state.db 入库 | ✅ | 完整保存（实测 11125 字符叠中叠一条不差） |
| 上下文压缩 | ⚠️ | config `compression.threshold: 0.5` 触发时，单条 >6000 字符被截成头4000+尾1500，**中间丢失**；`protect_last_n: 20` 保护最近20条 |

**外层发送者已修（2026-08-03 补丁）**：QQ 渲染引用消息只带被引用内容，**「谁转发的」不进渲染文本**——曾导致引用合并转发时上下文只显示子消息发送者（如「初晓·新雨」），丢外层转发者（如「（用户昵称）」）。补丁后 `_process_quoted_context` 加 `sender_nick` 参数（4 调用点传 author.username），quote_block 变 `[Quoted message from {昵称}]:`。详见 hermes-gateway-ops skill。

**验证方法：** 群消息处理后进 `state.db`（sessions 表 source='qqbot'），对比原文本长度即可确认是否断。超长聊天记录（>6000 字符）要提防压缩截断，必要时先把原文落盘。引用消息的图片 rkey 有时效（fileid 同 rkey 变），旧记录图片 URL 会 `appid is not match`。

## 短信钓鱼识别

收到短信问「能信吗」时，别只看链接——**文案模板 + 短链域名 + 落地页特征**三者组合判断。完整模式库（积分兑换/医保保险两类钓鱼模板、10 个真官方短链对照表、随机短域名直连坑、已知误报漏报）见 `references/sms-phishing-patterns.md`（2026-08-02 二十条短信实战沉淀）。一句话铁律：**「积分/XX分即将失效 + 可换华为手机/珠宝 + 陌生短链」= 诈骗**；「XX已入账/报销金打款 + 不验证作废 + 随机短链」= 诈骗；同文案不同域名 = 同一伙人批量撒网。链接本身的机器判定走 link-safety-check（`bin/linkcheck`），本 skill 负责话术定性。
