# AI 用量成本估算（token 宣称的换算方法）

> 用途：把「我花了 N 亿 token」这类宣称换算成钱，判断它离不离谱。**数字大 ≠ 贵，便宜 ≠ 成果大。**
> 结论口径：换算只给量级区间，不给精确值；**无账单/用量截图仍然只是「自述」**。

## 一、必守结构：三档单价 × 两个比例

总量拆成三段，各有各的价：

| 段 | 单价档位 | 谁造成 |
|:--|:--|:--|
| 输入·缓存命中 | 最便宜（常见是未命中价的 1/50～1/100） | agent 反复塞同一份 context／同一段代码 |
| 输入·缓存未命中 | 中等（常见是命中价的 50～100 倍） | 新文件、新对话轮次、首次读入 |
| 输出 | **最贵**（常见是命中价的 200～400 倍） | 模型实际写出来的一切（代码、解释、思维链） |

两个必须问清的比例：
1. **输出占比**——agent 式编程常见 2%～10%（写代码的场景输出偏多，只读不写的分析偏低）。
2. **缓存命中率**——多轮塞同一 repo/对话时 80%～95% 是常态。

**最常见的错法**：把总量全按「输入未命中」或全按「输出」单价乘一遍。前者高估约 4～5 倍，后者高估一个数量级以上。

## 二、可复制的算法

```python
def cost(total_tokens, out_ratio, hit_rate, price):
    # price: dict(hit=..., miss=..., out=...)，单位＝元/百万 token，由官方页现读
    out_tok  = total_tokens * out_ratio
    in_tok   = total_tokens - out_tok
    hit_tok  = in_tok * hit_rate
    miss_tok = in_tok * (1 - hit_rate)
    return (hit_tok/1e6*price["hit"] + miss_tok/1e6*price["miss"] + out_tok/1e6*price["out"])
```

出结论时给矩阵而不是单点（输出占比 × 命中率），再点出「典型 agent 编程形态落在哪一格」。同一总量下，输出占比 2%→10% 能让账翻 2～3 倍；命中率 50%→95% 也能让账掉一半以上。**这两个维度必须分开报，否则读者会把「便宜」误读成「没干什么活」。**

## 三、价格从哪来

- **现读厂商官方 pricing 页**，别背：三档结构（命中/未命中/输出）＋高峰/空闲半价是多数国内厂商的共同形态；中文页通常一屏给全。
- 官方页面常带一条对人有利的细节：**空闲时段（夜间、周末、法定节假日）价格减半**。工程时间戳若覆盖假期，账再砍一半——但这是**加成事实**，不是结论。
- 汇率/促销/赠金会改变结论：**赠金不能当现金等价物**写进结论。

## 四、要和哪几条一起写

1. **速率校验**：总量 ÷ 工程天数 ÷ 86400 = 每秒 token。超出单会话量级（几十～几百 tok/s）就只能说「必须多 agent 大规模并行才成立」——不能证真，也不能证假。
2. **归属校验**：token 数不区分「从零写」与「照着开源改」。查历史视频简介里的仓库链接、评论区作者自述、工程目录文件时间戳，分清自研部分与拿来的部分。
3. **成果校验**：能不能跑、有没有人复现、有没有仓库可查——这三件事与花了多少钱没有关系，分开报。
