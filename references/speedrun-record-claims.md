# 速通「作弊／封号／世界纪录」类主张的核验（speedrun.com）

> 用途：圈子里出现「某人的世界纪录被官方下架／被封号」「某人是世界第一」这类主张时，用**平台官方状态**判结果。
> 打假方/吹捧方的视频标题只是线索，不是证据——标题里写「已实锤作弊封号」也不等于官方下架了纪录。

## 端点（`www.speedrun.com/api/v1/…`，免 key）

| 要什么 | 请求 |
|:--|:--|
| 找游戏 id | `/games?name=Metal%20Slug&max=30` |
| 各分类当前纪录 | `/games/{game_id}/records?top=1&scope=all`——`category`／`times.primary_t`（秒）／`players[].id`／视频链接／日期 |
| 按名字找用户 | `/users?name=<词>&max=5` |
| 用户状态 | `/users/{user_id}`——**`role`** 字段（`banned`＝封禁）＋`signup` 注册日 |
| 名下纪录 | `/users/{user_id}/runs`（被清空时整条路回 **404**）、`/users/{user_id}/personal-bests`（回空数组） |

- ⚠️ **HTML 页（`www.speedrun.com/mslug3`）会 403（Cloudflare），API 200**——判「这站不可达」之前先打 API，别拿 HTML 的 403 下结论。
- 玩家 id 是短码（形如 `814v7vp8`），榜单/用户搜索返回的就是它，直接喂 `/users/{id}`。

## 判据与口径

- **封号＋记录清空＝一手实锤**：`role: "banned"` 且 `runs` 404、`personal-bests` 0 条 → 「被官方封禁、纪录下架」成立。这是**平台方**给的结论，与举报方说了什么无关。
- **交叉佐证**：看该游戏各分类当前 WR 是否换人（原持有者名字不再出现）。
- **只坐实「结果」，不坐实「手法」**：官方状态能证明「被封了」，证明不了「用了什么作弊手段」——存档读档字样、TAS 冒充实战这类要看**举报方的实证材料**（原图／原始录像／原始链接），单独列一条，别写成官方结论。
- **申诉状态可查**：举报方常引用 `/users/<name>/pending?view=rejected`（申诉被否）——这是可复现的引用路径，跟着打一次。
- **落档时把端点原文写进证据行**（哪条 API、返回了什么字段值），否则下一个人只能照抄结论、无法复核。

## 常见坑

- 拿「现在榜单上没有他的名字」当「被下架」——排行只显示在榜纪录，**不能区分「从未提交」与「被删」**；要区分得看用户页的 `role` 与 runs/PB。
- ban 的原因与时间 API 不给（只有 `role` 这个状态位）→ 别编时间线；去举报方节目里找带日期的界面截图（简介常附原始链接）。
- 站内 HTML 与 API 的可用性会翻转，**每次先打最便宜的 API 探一次**再决定要不要找替代源。
- 同一游戏可能有多个版本/分类条目（原版、Bootleg、Legendary 版各占一个 game id），报「世界纪录」前先确认是哪个 id 的哪条分类。
