# Quick Fact Check · 快速事实核查

> 适用：用户扔过来一张图、一条链接、一句"这个是真的吗"，需要快速给出结论。
> 不适用：整点新闻摘要、深度研究报告、多轮数据验证。
> 📄 踩坑表/聊天记录解析/短信钓鱼/VTuber 速查 → `references/pitfalls-and-special.md`

## 铁律

**能自己并行搜完的，绝不派小队。** delegation 给推理密集/多步流水线/大数据整合，不是给简单搜索的。

**缩写多义先穷举候选再下判断。** ⚠️ 2026-08-01 踩坑：图传「SD 2.5」被默认当成 Stable Diffusion 查无实据标了假，实为字节 Seedance 2.5（视频生成模型）。缩写（SD/GLM/GA 等）至少 2-3 个候选义，先列出候选分别搜一轮再判，别默认最常见解读——发图的人可能用圈内简称。

**隐喻式提问先换视角再下结论。** ⚠️ 2026-08-01 踩坑：用户发外卖支付成功截图问「有多少坑位」，vision 第一轮答「没有坑位/格子结构」——被点醒才明白坑位是**隐喻**，指图上金融营销入口。mmx 只描述字面（卡片/按钮/格子），问「坑位/陷阱/套路」时别急着报「没有」，换 prompt 重跑：「识别图上营销入口/诱导位/金融坑位」。

**古语/雅语先查成语本形再定性。** ⚠️ 2026-08-02 踩坑：群友说「当浮一大白」，自己当「文言客套夸奖」接住了——实际是成语「**浮一大白**」（西汉《说苑》「饮不釂者，浮以大白」，满饮一大杯）的用法变体（「当」=应当），**不是夸人**。典故引用以原文为准，出处多源核实（成语词典+圈内实证），别凭字面语感定性质。

**截图溯源先抠作者名再匹配。** ⚠️ 2026-08-11 踩坑：知乎问答截图（原神 TGA 帖）按标题搜命中多条回答（呆罗/教主），标题几乎一样，按标题匹配会落到错人——vision 识图先抠出作者名「教主」，再用搜索结果 `author_name` 逐条对，才找到 answer/1621590690。**底部更新段落也要对上**（教主回答 2021-05-13 追加的「西山居调查邮件」澄清段正是截图底部内容）。vision 没读出作者名时，换 prompt 专门抠「作者名/头像/时间戳」再跑一轮。

| 做 | 不做 |
|:---|:-----|
| 3轮并行 搜索入口（作者环境是 `mmx search`） | 派 delegation 绕路 |
| 视觉入口（作者环境是 `mmx vision describe`） 直接看图片 | 串行搜索浪费回合 |
| 收到就动手，搜完就报 | 先建计划再执行 |

## 标准流程

```
接收内容
  │
  ├─ 是图片 → 视觉入口（作者环境是 `mmx vision describe`） --image <path> --prompt "详细描述图片内容"
  │            → 提取标题/角色/品牌/关键文字
  │
  ├─ 是链接 → 直接提取关键信息（标题/摘要）
  │
  └─ 是文字 → 提取可验证事实点
       │
       ▼
  并行 搜索入口（作者环境是 `mmx search`） ×2~3，不同关键词不同角度
       │
       ▼
  比对：
  - 各来源 date 字段一致（时效）
  - 至少 2 个独立来源吻合才采信
  - 图片识别的文字可能不准 → 以搜索结果交叉校验
  - 外部 IP（VTuber/UP主/作品）→ 官方渠道形象对比：拉官方空间头像/频道图比对角色特征，比纯搜索快（2026-08-05 实锤 Neuro-sama 案）
       │
       ▼
  出结论：
  - ✅ 确认 → 关键信息：日期/当事人/出处
  - ❌ 存疑 → "只找到这些，等用户确认"
```
