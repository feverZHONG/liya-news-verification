# 核查细节（流程/陷阱/闭环）

> SKILL.md 留触发+核心规则表，本文件放流程细节、常见陷阱、根因闭环与踩坑实例。

## §4 核查流程

```
① 识别输出中所有"可验证事实"（比分、数字、日期、事件）
② 对每个事实执行针对性搜索验证
③ 跨来源比对（至少2源一致才可信）
④ 确认日期新鲜度
⑤ 与前一次输出对比去重
⑥ 只有全部通过才放行到最终输出
```

**当目标源被封锁时的验证策略：**
- ANN/MyAnimeList/日本站被 Cloudflare 拦截 → 切换至 Bing 中文版搜索，从 HTML 解析结果 snippet 获取摘要
- Google curl 超时 → 换 Bing，加上 `&setlang=zh-Hans` 参数
- 百度触发 CAPTCHA → 用 Bing 而非百度作为搜索入口
- 从 Bing 结果提取 URL 后直接访问源站（如腾讯新闻、百度百科），这些页面常含硬编码 JSON（`window.DATA` / `window.PAGE_DATA`）可直接提取验证
- 详见 `chinese-news-aggregator` 技能 §9：Bing 兜底搜索方案

**mmx 搜索实测要点（2026-08-01）：**
- 语法：搜索入口（作者环境是 `mmx search`） query --q "关键词" --output json --quiet`（`search web` 是同一命令的别名）
- JSON 结果在 `organic[]` 数组，每条含 `title / link / snippet / date` 四个字段；**`date` 是过滤旧闻的第一依据**
- 单次最多返回 **10 条、无分页**，`--count` 参数无效 → 想换一批结果只能精炼/更换 `--q`
- 批量采集可直接复用现成的采集脚本（作者环境那份已处理 JSON 解析与去重；未单独公开）

## §5 常见陷阱

- ❌ 搜索片段提到"法国晋级16强"→ 脑补"法国6-4英格兰"
- ❌ 源A说"443.2万辆同比71.7%"，源B说"531万辆"→ 混成一条"531万辆同比53%"
- ❌ 看到"第N次"的旧闻 → 原样当新发布
- ❌ 搜索没找到匹配结果 → 不编造，标记"未找到验证来源"
- ❌ **mmx/搜索引擎按相关度排序，2024~2025年旧闻可能排在今日新闻前面** → 追加日期限定词再搜一轮，日期字段>2天的直接丢弃
- ❌ **日期关键词触发"同月同日历史污染"**：搜 "8月1日 新闻"、"台风白海豚 8月1日" 会混入 2018/2020/2023/2024 年**同月同日**的旧稿（旧台风路径、旧A股收盘、旧新闻联播）→ 按结果自带 `date` 字段逐个过滤年份，再用常识核对（当年台风编号、指数点位量级），不能只看标题像不像
- ❌ **记录类说法单源采信**："创XX年以来最大单日涨幅/跌幅""首次""史上最大"类声明最易双源冲突（实测：亚马逊涨幅 每经"2012年以来" vs 财联社"2022年11月以来"；苹果跌幅 6% vs 8%）→ 铁律：至少2源、双方口径都注明，正文用保守表述（"涨超15%创多年最大单日涨幅"），精确差异进待验证区

## §6 找到根因再收工（流程改进闭环）

验证发现错误后，**不要只修正当前输出**。找到产生错误的流程环节并修复它。

### 本技能的调用场景

| 上游 | 触发时机 |
|:-----|:---------|
| 📰 简报类 skill（步骤④-⑤） | 简报整合前，对每批回传数据进行事实核查 |
| 任何涉及事实数据的搜索→输出类任务 | 交付前，对可验证事实执行核查 |

### 流程改进闭环

```
验证发现错误 → 判断错误来源
                    ↓
      ┌─────────────┼─────────────┐
      ↓             ↓             ↓
 搜索词不够具体  整合阶段脑补   日期门槛太松
      ↓             ↓             ↓
  更新搜索策略   调低AI自由度   收紧时效规则
```

**铁律：** 当同一个坑连续出现两次（如体育比分编造、旧闻复用），根因不在搜索结果里，而在**生成过程的某个环节缺了检查闸门**。此时应更新上游工作流，不只是在当前输出上打补丁。
