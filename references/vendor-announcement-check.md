# 厂商官宣核实 · 一手源与画饼判定

> 案例：2026-09-10《合金弹头》30 周年（《METAL SLUG ULTIMATE COLLECTION》＋ 宣传片结尾卡「A NEW METAL SLUG IS ON THE WAY」）。
> 触发场景：用户甩来官宣截图/宣传片，问「这是真的吗」「是不是还在画大饼」。

## 1. 为什么停在聚合站会错

同日实测（同一事件）：

| 源 | 结果 |
|:---|:-----|
| 厂商自家 PR 页（snk-corp.co.jp） | ✅ curl 直取，全文硬字段 |
| zhuanlan.zhihu.com（SNK 官方号文章） | ❌ 403（正文可从 qsearch snippet 拿到片段） |
| insider-gaming.com / gematsu.com | ❌ 403 |
| Notebookcheck / GameApps.hk / LevelUp / Inven | ✅ 可读，但都是**二手转述** |

**结论**：聚合/媒体源能确认「公众怎么理解」，只有厂商 PR 能确认「官方怎么说」。
口径差异实例：官方中文 PR 写「传说中的试玩版」，Steam/小黑盒文案写「Location Test 版」——落档以官方为准。

## 2. 一手源找法（实测路径）

```bash
# ① 找 PR 索引页（多数日系厂商都有 /press/ 或 /news/ 目录）
curl -s "https://www.snk-corp.co.jp/cn/press/" -H "User-Agent: Mozilla/5.0" \
  | grep -oE 'href="[^"]*press/2026[^"]*"' | head -30
# ② 挑出当期那条（标题 URL 编码也在，肉眼可辨）
# ③ 读全文
`read-url`（作者环境的正文提取命令） "<PR URL>"
```

本轮 PR 一次给出的硬字段：收录 10 作逐作年份+原平台、功能清单（快存/回溯/分数挑战/限时挑战/战斗学院/在线排行/画廊博物馆）、平台五件套、**价格「未定」**、愿望单已开、周边企划与截止日。

⚠️ **各语种官方渠道不同步**——SNK 中国 B站官方号（`bili_dyn_walk.py <mid>` 翻页）本轮只有 4/19 与 9/9 两条动态，6 月的「双新作」官宣是从日文/英文渠道发的。**别拿某个官方号没提就判定「没官宣过」**，换语种渠道再查。

## 2.5 特设站是 SPA（read-url 只出首屏片段）的兜底

本轮 ``read-url`（作者环境的正文提取命令）` 读官方特设站只拿到 Feature 01，**Feature 02（署名那条）/03 全缺**。改用 curl 原 HTML + 剥标签：

```bash
curl -s -m 30 -L "<特设站URL>" -H "User-Agent: Mozilla/5.0" -o /tmp/p.html
python3 - <<'EOF'
import re, html
t = open('/tmp/p.html', encoding='utf-8', errors='replace').read()
t = re.sub(r'<(script|style)[^>]*>.*?</\1>', '', t, flags=re.S|re.I)
t = re.sub(r'<[^>]+>', '\n', t); t = html.unescape(t)
out = []
for l in (x.strip() for x in t.split('\n')):
    if l and l not in out[-3:]:
        out.append(l)
print('\n'.join(out)[:3000])
EOF
```

实测一次拿回全部 Feature 段 + 规格字段（Genre／玩家人数／发售日／价格／评级），比 read-url 完整。**官网特设站优先用这个姿势**，read-url 只当快读。

## 3. 画饼判定三问（模板）

| # | 问什么 | 判据 | 本轮实例 |
|:--|:-------|:-----|:---------|
| 1 | 这是第几张卡？ | 拉时间线，数标语卡的张数；卡越多新增信息越少 = 卡是空的 | 4/19「MISSION REBOOT / A NEW MISSION AWAITS」→ 6/12「双新作」→ 9/9「A NEW METAL SLUG IS ON THE WAY」 |
| 2 | 有没有具名的人/组织在推？ | 采访人证/例会/编制 > 只有标语 | 品牌经理 Seungju Song（企划命名）、Neo Geo 元老 Naoto Abe（监督项目）、每月两次跨部门会议（日经 Gaming Japan 采访） |
| 3 | 同期有没有能交付的实物？ | 有实物 ≠ 承诺兑现；实物系第三方代做要分开记 | 合集 2027（收录/功能/平台都落地） |

**结论模板**：「项目是真的（有人有例会连续表态），但这张卡本身零信息量（无名字/平台/日期/画面），能拿到手的实物只有 X。」——两句分开说。

## 4. 署名红线（2026-09-10 当日二改 —— 这一条本身就是反例）

**「官方 PR 没写」≠「官方没署名」。官方信息面要逐层走全，再下结论。**

| 层 | 位置 | 本轮结果 |
|:--|:-----|:---------|
| ① | PR／新闻稿（多在 `/press/`，**中文站与日文站分开发**） | 收录/功能/平台/价格「未定」——**但无开发方署名** |
| ② | **产品官网／特设站**（`/official/<title>/`） | ✅ Feature 02「数々の名作タイトルの復刻を手掛けてきた**エムツーが移植開発を担当**」 |
| ③ | 商店页（appdetails 的 developers/publishers） | 只到发行层，不写移植方 |
| ④ | 官方 SNS（各语种账号） | 跟进宣传，不写开发方 |
| ⑤ | 实机 / Staff roll | 未发售，暂不可用 |

**教训本体**：本轮合集开发方曾被记成「SNK×M2（エムツー）」→ 复核时**只翻了中文 PR**（无署名）+ M2 官网无该项目 → 判「查无出处」并**撤回**；随后翻官方特设站 Feature 02，**结论直接反转——原始说法是对的，是复核方法不完整造成误撤**（当日二改）。

绑定纪律：
- 走全五层仍无 → 才标「待核」
- 走全之前**不许**下「没有」的结论
- 任何时候都**不许**凭「这家名声对得上」补工作室名；有来源才写，写就带来源出处
- 具名人物一律连 **人 + 职 + 来源 + 年月**

## 5. 复用清单

1. 找厂商自家 press 索引页（不是聚合站）
2. curl 列表页 → grep 当期 URL → `read-url` 读全文
3. **特设站/产品官网单独走一遍**（SPA 用 §2.5 剥标签法）——署名、规格字段常只在这儿
4. 换语种官方渠道复核（B站动态翻页 / 日文官网 / 英文 PR）
5. 拉全部同期官宣拼时间线，数「第几张卡」
6. 判断三问 → 分开下判（项目 vs 这张卡）
7. 落档：官方口径单列，商店/媒体口径标注来源；**署名走全官方信息面后再写**

## 6. 「全面超越」类宣称核对（性能/基准）

> 案例：2026-09-10 DeepSeek V4 Pro 下线（官方称 V4.1 Flash「全面超越」），真实主因疑为 0813 **泛化失败/过拟合**。
> 触发：官方公告说「新款在性能/费用/速度/总用时上全面超越旧款」，或某型号被下线/被路由/被合并。

官宣的「超越」是**话术**不是结论——去换一把尺子。

### 6.1 三个交叉检查

**① 自家 harness vs 中立 harness（最硬的一刀）**

厂商基准表只证明「在厂商的尺子上它很好」。找第三方用中立 harness 复测同项：

- **CoderSera** —— 中立 harness 复测（本轮关键数字来源）
- **Artificial Analysis** —— Intelligence Index / AA-Omniscience 事实可靠性
- 社区横评 —— B站/知乎/头条「我测了下，怎么跟他们说的不一样」类

| 分差 | 结论 |
|:-----|:-----|
| 5~10 分 | 正常水分 |
| **30 分以上，或排名翻转** | **尺子被适配过**（基准适配/过拟合），不是「略有余量」 |

实例：V4 Pro 0813 官方 harness Terminal-Bench 2.1 **87.9**；CoderSera 中立 harness **54.68**（掉 33 分），同条件下自家小号 V4 Flash **67.04**——**旗舰被小号反超 12 分，排位颠倒**。旁证：AA-Omniscience 给 0813 打 **0.83**，同期 Opus 5 为 **37.07**。

**② 改动量对得上跑分涨幅吗**

读 change log / 技术拆解，问：**架构换了吗？参数量动了大头吗？**

- 只是 serving 效率/推理加速/解码优化（投机解码之类）→ **不该出现单项 +50 分跃升**
- 「架构没换 + 参数微调 + 跑分暴涨」配上①的 33 分回落 = 结论自己就出来了

实例：0813 仅增四个 DSpark key、约 517 亿参数（投机解码/serving 效率），核心规格与 7 月 GA 一致；官方 harness 上 DeepSWE 12.8→62.7、CyberGym 52.7→83.3。

**③ 时间线闭合——官方动作会说话**

- **上线当晚就曝撤回** ＝ 官方自己第一时间就知道有问题
- **之后长期零解释** ＝ 不打算解释
- **收场叙事 =「被更强的新款全面超越」** ＝ 最省事的止损：不必承认旗舰训练出了问题，只需有个更强的继任者

实例：08-13 上线 → 当晚曝紧急撤回（腾讯新闻）→ 08-16 口碑争议 → 08-17「跑分暴涨源于对标准测试集的强化」→ 08-21「频繁早停/训练过拟合」讨论 → 09-08 内测 → 09-09 路由 → 09-14 下线。**旗舰存活 31 天。**

### 6.2 判读纪律

- **「全面超越」的信息量取决于被超越方**——被超越方本身泛化失败时，这句话门槛趋近于零（不需要新款多强，只需旧款够弱）
- **解释不了对照组的归因要警惕**：8 月中旬「极简模式/配置错装」的辩护能解释「时好时坏」，但解释不了「**同一调用路径下被 Flash 反超 12 分**」→ 判为口碑危机中的公关性归因
- **程度保留，别一竿子打翻**：泛化失败 ≠ 全线归零（0813 在 CyberGym 类窄域第三方仍承认领先）。准确表述是「**泛化能力配不上其定价与定位**」——拿价格/并发档位当量化锚
- **三层分源写清**：厂商基准＝官方宣称 / CoderSera·AA＝第三方（注转引链）/ 用户判断＝判断。别混成一锅，**更别把判断写成数据**
- **可复用追问**：新款上线后，第三方是否也给出「自家高、中立低」的鸿沟？若是 → 问题在**训练方法**，不在单一型号
- **下游衔接**：官宣里的新时间点若全网无源，别当假也别当已证实 → 判「官方一手待确认」（见 `deepseek-official-sources.md` 迭代期公告核对节）

### 6.3 源可用性（本轮实测）

中文科技媒体实测类文章反爬严重：今日头条要 JS、36氪「安全检测」、longbridge 连接重置。对策：用 mmx/qsearch 拿 snippet + 能直读的外媒（aitoolsreview 这类）交叉，**别在一篇上耗死**。DeepSeek 官方渠道核对 → `deepseek-official-sources.md`。
